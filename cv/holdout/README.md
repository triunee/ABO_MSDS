# 최종 확인용 문서(holdout) 17건

- 작성 2026-11-27. **이 문서들을 누구도 열기 전에** 목록을 봉인하고 커밋한다(`docs_manifest.csv`). 이 커밋 시각이 텍스트 추출 · 정답 작성 · 추론보다 앞선다는 것이, 확인용 문서를 결과에 맞춰 고르지 않았다는 근거다.
- 공개 저장소이므로 문서 이름 · 제조사 · 정답에서 나온 값을 어떤 파일에도 적지 않는다. 자료 위치는 `<HOLDOUT_ROOT>`(저장소 밖)로만 적는다.

## 1. 무엇인가

- 새 test(`cv/prereg_newtest.md`)를 고를 때 쓴 문서 묶음에서, 선별 규칙(사전 등록 2절)을 모두 통과했지만 50건을 채운 뒤라 선택되지 않은 문서 30건 중 일부다.
- 고른 규칙(기계적으로 적용, 사람이 넣거나 빼지 않음): 그 30건 중 **제조사 그룹이 새 test 50건과 겹치지 않는 문서 전부.** 교차검증 45건의 제조사(관계사 포함)와 파일럿 노출 문서는 선별 규칙 3 · 4에서 이미 빠졌다.
- 결과: **17건 · 제조사 그룹 15개**(그룹당 1~2건). 서식(현행 · 수입품 국문판 · 구서식)은 텍스트를 만들 때 정한다.
- 새 test에서 제조사가 겹쳐 빠진 나머지 13건은 확인용이 아니다(학습용 후보).

## 2. 봉인

| 파일 | 내용 | 언제 |
|---|---|---|
| `docs_manifest.csv` | 원본 PDF 17건의 비밀 키 해시(`pdf_hmac` 17 · `pdf_hmac_set` 1), 파일 이름 없음 | 2026-11-27, 문서를 열기 전 |
| `test_manifest.csv` (예정) | 정답 · 텍스트 · 서식 · 그룹 4종의 비밀 키 해시 | 정답 확정 뒤, 첫 추론 전 |

- 해시는 `eval/seal_docs.py` · `eval/seal.py --key-file`로 만든다. 키는 저장소 밖(`<HOLDOUT_ROOT>/seal/`)에 있고 새 test 키와 다르다. 키 없이는 해시를 만들 수 없으므로, 같은 PDF를 가진 사람도 어떤 문서가 확인용인지 맞춰 볼 수 없다.
- 대조: `python3 eval/seal_docs.py --verify --pdf-dir <HOLDOUT_ROOT>/pdf --key-file <HOLDOUT_ROOT>/seal/hmac_key.txt --manifest cv/holdout/docs_manifest.csv`

## 3. 규칙

1. **열기 전까지:** 텍스트 · 내용을 개발 판단(전처리 · 프롬프트 · 출력 보정 · 대응표 · 학습 데이터 · 조건 선택)에 쓰지 않는다.
2. **정답 만들기:** 그때 HEAD의 `docs/plan.md` 2절과 `data/README.md`를 그대로 따른다. 확인용 문서를 보고 규칙을 고치지 않는다. 규칙에 없는 경우는 저장소 밖 메모에만 남긴다.
3. **봉인:** 정답 · 텍스트 · 서식 · 그룹을 `eval/seal.py --write --key-file`로 `cv/holdout/test_manifest.csv`에 봉인하고, 커밋한 뒤에만 추론한다.
4. **쓰는 횟수:** 사전 등록한 비교마다 1회만 추론 · 채점한다. 결과를 보고 기준 · 비교군 · 보정 규칙을 바꾸지 않는다. 바꾸려면 새 사전 등록을 만들고, 그 결과는 "확인용을 한 번 본 뒤"로 따로 적는다.
5. **학습 데이터와 겹치지 않게:** 새로 학습에 넣는 문서(예: 새 test 50건, 팀 test 국문 18건)가 이 17건과 제조사(관계사 포함)가 겹치면 그 문서는 학습에서 뺀다. 팀 test 목록은 저장소 밖에 있어 넣기 전에 따로 대조한다.

## 4. 한계

- 17건 · 15개 그룹은 방향 확인 규모다. 문서 수 · 그룹 수와 함께 보고한다.
- 정답을 만드는 사람이 개발자 본인이다. 2차 검수자가 없다.
- 새 test와 같은 묶음에서 나왔으므로, 문서를 모은 출처 · 시기는 새 test와 비슷하다. 완전히 다른 출처의 문서로 일반화된다는 근거는 아니다.
